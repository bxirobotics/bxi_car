# 现有 App 接入 car2

适用于同一块主板、同一台工控机：保留 `car2` 的 BXI/CAN/EtherCAT 驱动、机械参数、零偏和控制循环，在相邻 `app/bxi_rc_ros2` 网关增加 `car2` 后端。手机端继续使用已有 Wi-Fi/BLE 鉴权、控制权、安全过滤和 OTA 页面。

## 接口

| 接口 | 含义 |
| --- | --- |
| App `vx/vy/wz` | 归一化比例 `[-1,1]`，按网关配置换算；本机底盘速度上限保持 `1.0 m/s` |
| `/cmd_vel_car`，`geometry_msgs/Twist` | 网关转换后的车体速度，X 向前、Y 向左、yaw 逆时针；保留控制器 300 ms 断流停车 |
| `/car2/ready`，`std_msgs/Header` | 硬件初始化和校准完成后，每次成功控制周期发布；网关 300 ms 收不到即判离线 |
| `/car2/state_machine_info`，`std_msgs/String` | 每 100 ms 发布当前状态和动态动作清单；不伪造关节反馈 |
| `/car2/arm_command`，`std_msgs/Int8` | 网关将专用 `btn_10` 值转换成一次动作；发布端保留最新消息并设 100 ms 有效期 |
| `/car2/app_control`，`std_msgs/String` | 共享模式统一输入：同一帧携带模式、时间戳、三轴和动作，避免机械臂输入流入底盘 |

独立模式中，App 启动无手柄节点的 `chassis`；仅底盘使用 `chassis_only`。共享模式中，App 和手柄都向常驻 `robot_control` 请求启停，由同一个控制器管理硬件。启动过程沿用本机配置的回零和校准行为。`app_interface_enabled:=true` 启用 App 状态与机械臂接口。导航速度的归一化比例与出口比例保持一致，输出不会回流到导航输入。

## App 与手柄共用主控

`deploy/ros_elf_launch.service` 以 `shared_control:=true` 运行 `robot_control`，ROS domain 与网关统一为 22。程序启动后停在 `waiting`，只有 App 启动请求或手柄按钮 14 才进入硬件初始化；不会因常驻进程存在就显示硬件已启动。正常停止完成后，旧进程短暂保留状态接口供客户端确认断电，再退出，由 systemd 的 `Restart=always` 启动新进程回到等待状态，需等数秒后才能再次启动。新进程不恢复旧启动请求或摇杆输入。硬件故障则锁存 `fault`，排除原因并重启进程后才能再次启动，故障不触发这条自动重建路径。

BXI 厂商库的 `bxi_pci_exit()` 只重置控制器并解锁，不结束收发线程；同进程再次初始化会产生多个线程共用 CAN 队列。因此每个进程只允许尝试一次板卡初始化，正常停止后的下一次硬件会话必须使用新进程。硬件锁保留至旧进程退出；自行直接运行共享模式时也需要外部进程管理器才能自动恢复等待。

网关持久配置启用 `BXI_CAR2_SHARED_CONTROL=1`，通过 `scripts/shared_control.py` 请求 `/run/car2/control.sock`。App 不再单独启动或杀死控制进程。只有验证过的共享主控 PID 可从启动冲突中排除；其他控制器仍会被拦截。硬件初始化和校准完成后的成功控制周期才发布 `/car2/ready`。

- App 启动时取得初始控制权；手柄启动时由手柄持有。
- 手柄新的实际操作可以接管，初始化事件、已有持杆状态和未持权方的零指令不会抢回控制。
- App 通过动作栏的“App 接管控制”（`btn_10=110`）明确接管，随后回中一次再操作。
- 每次切换先清除旧速度、机械臂目标和跟踪请求，机械臂停稳后再接受当前控制方的动作。首次手柄步进仅能在本次控制权内暂存最多 300 ms，超时或失权即丢弃。
- 手柄按钮 11 和 App 停止均为全局停机。失联或速度心跳超时撤销持权方，不自动恢复另一方的旧指令。

共享模式的 App 使用 `/car2/app_control`，JSON 固定六字段：`stamp_ns`、`mode`、`vx`、`vy`、`wz`、`action`。`mode="chassis"` 时三轴是 m/s、m/s、rad/s；`mode="arm"` 时三轴是末端 X、Z、pitch 的归一化输入 `[-1,1]`。主控拒绝超过 100 ms、切换前、重复和非持权方指令；每次切模式先停止旧运动，收到三轴零且 `action=0` 的新帧后再允许运动。尚未接受统一输入时，旧 `/car2/app_cmd_vel` 保留底盘控制，旧 `/car2/app_arm_command` 保留停止和接管；前三轴移动需要新的机械臂模式输入流。开始统一控制后，不再允许分离的旧运动消息覆盖模式，显式接管 110 仍可用。旧 `/cmd_vel_car`、`/car2/arm_command` 和公开调角参数不能绕过共享控制权。

视觉启停参数携带本次控制权代数。视觉目标使用 `/car2/arm_tracking_target` 与 `/car2/arm_tracking_goal_target` 的 String JSON，包含 `generation`、`stamp_ns`、`frame_id`、`x`、`y`、`z`。固定目标可额外携带本轮唯一的 `stroke_id` 以请求行程复核。主控在 `/car2/arm_tracking_stroke_state` 发布同代数、同行程的停稳时间和阶段，`/car2/arm_tracking_correction` 至多接受一次与该回执匹配且观测时间新鲜的补差。

只读检查：`sudo python3 scripts/shared_control.py status` 或 `preflight`。它们不会请求上电；`start` 则会执行本机配置的初始化与回零。当前 elf3-59 的服务使用 `/home/bxi/tang/car2` 源码构建和该目录的标定配置，修改 `/opt/bxi/car2` 包不会自动替换此服务的可执行文件。

## App 机械臂模式

机器人就绪并声明 `capabilities.car2_arm_control=1` 后，App 提供机械臂模式。左摇杆上下控制末端前后 X，右摇杆上下控制 pitch；忽略横轴，底盘保持停车。X/Z 四个按钮点按请求 1 mm，长按持续移动，松开减速停止并保持；短点按后的中立帧允许这一步完成。App 进入模式时明确接管，并先回中；退出、后台、断连或失去控制权时清除输入并停止。状态中的 `control_owner` 经网关转发为 `control.state.metadata.control_owner`。

连续控制复用已有 PP、IK、限位和转矩保护。输入最大参考速度为 X/Z 5 mm/s、pitch 1°/s，实际运动仍受电机 profile 和反馈限制；目标相对反馈的前视不超过 1 mm、0.2°，不会在忙碌时堆积目标。机械臂有独立 250 ms 输入租约，底盘心跳不能续期。物理手柄 X/Z 默认步长同为 1 mm（`arm_translation_step_m=0.001`），保留长按每 0.1 s 尝试一步、回中停止重复；忙碌时丢弃重复请求。手柄 pitch 和校准脚本保持原行为。

Wi-Fi 使用专用 `control.arm` 消息；BLE 使用 v4 的 25 字节头（v3 原头追加 mode=14），鉴权覆盖完整新头。普通底盘保留 v3。旧版本缺少能力声明时不能启用新的机械臂模式，App、网关与主控需要同步升级。

机械臂动作值如下：

| `btn_10` / Int8 | 动作 |
| --- | --- |
| 101 / 102 | 末端 X 正向 / 负向 1 mm，仅机械臂模式三轴中立时接受 |
| 103 / 104 | 末端 Z 正向 / 负向 1 mm，仅机械臂模式三轴中立时接受 |
| 105 / 106 | 已移除，接收端拒绝；pitch 改用右摇杆 |
| 107 / 108 | 第四轴正向 / 负向短点动，最多 100 ms 的指令窗口 |
| 109 | 取消机械臂目标、停止视觉跟踪，减速停止并保持 |
| 110（仅共享模式） | App 接管控制；切换后需先回中 |

前三轴经过现有 IK、关节限位、姿态分支及视觉控制权检查；忙碌或不可达请求会拒绝并记录日志。第四轴沿用现有限位、PP 模式和位置记忆，不持续锁存按键。三轴配置不显示第四轴动作，仅底盘配置不显示机械臂动作。点动动作只消费一次，长按通过新鲜连续输入维持，不把一次点击重复为多步。断链或安全门关闭时发送 109，且主控独立租约可在没有新帧时停止；重复停止不重复操作硬件。

## 启停与升级

通过持久配置 `/etc/bxi/control_backend.env` 设置 `BXI_CONTROL_BACKEND=car2`；网关和 car2 必须继承同一 DDS/ROS domain。默认给回零和校准保留 900 秒启动等待，期间 App 的停止按钮可取消启动。Wi-Fi 状态提供 `start_timeout_sec`，BLE 使用 900 秒默认值；自定义更长等待时使用 Wi-Fi。独立模式停止进程退出宽限为 15 秒；共享模式先确认硬件关闭，再重建等待进程，不自动重新上电。

OTA 把独立 `car2` 包替换到 `/opt/bxi/car2`，用它替代旧 RL Controller 的升级项。控制程序与 OTA 部署持有同一文件锁，运行时拒绝部署；标定、配置、第四轴位置记忆和日志留在包外。首次迁移、构建、制包及升级操作见 [car2_ota.md](car2_ota.md)，持久环境样例见 [car2-app.env](../deploy/car2-app.env)。缺少本机第四轴可信位置记忆时，应从原运行目录迁移，程序不会假定零位。

## 验证边界

离线检查覆盖单位转换、状态和按钮协议、失联、启停取消、配置迁移、锁互斥、制包校验和失败回退。编译或测试不启动主控硬件。真实机器仍需验证首次回零/校准、摇杆方向、机械臂动作、停机及升级后的重新启动；相同主板和电脑不能替代这些运动验证。
