# 意优按键转矩调节

校准入口默认手动松闸；本页转矩调节需要显式指定 `--control-mode torque`。
启动目标为0，所有电机保持未使能。左右选轴，上下每次将所选轴的请求目标增减
0.05 N·m（电机轴侧），第一次调节时才使能该轴。切换选轴不会清除其他轴的目标。
这会持续施加目标出力，不能保证只转动1°，零转矩也不保持位置。

空格清零所有目标并失能；命令执行中按空格会中止并退出断电。q / Ctrl-C 退出断电。
z 保存当前轴零点前，要求其他轴全部失能；当前轴清零失能后还必须确认静止。
保存后不恢复出力，下一次按上下键从0重新计算。转矩模式拒绝第4轴，保留其已有位置限位契约。

```bash
# 预览，不访问电机。
bash start_yiyou_jog.sh --dry-run --interface enp86s0 --slaves 1,2,3 --control-mode torque

# 实际执行会控制共享电源；之后等待按键。
sudo bash start_yiyou_jog.sh --interface enp86s0 --slaves 1,2,3 \
  --control-mode torque --speed-rpm 0.2 --torque-limit-nm 100

# 显式恢复位置点动；没有默认启动运动。
sudo bash start_yiyou_jog.sh --interface enp86s0 --slaves 1,2,3 \
  --control-mode position --speed-rpm 0.2
```

## 单位与量化

依据意优官方《PHU&RHU系列关节CANopen与EtherCAT通信手册》V1.11：
[文档下载页](https://eyoubot.com/documents)，
[通信手册PDF](https://file.eyoubot.com/document/EYou-PHU%26RHU%E7%B3%BB%E5%88%97%E5%85%B3%E8%8A%82CANopen%E4%B8%8EEtherCAT%E9%80%9A%E4%BF%A1%E6%89%8B%E5%86%8Cv1.11-20261010.pdf)。

- §4.6.3（印刷59–62页）的CST使用模式10。
- 6071详细中文说明（236页）以额定电机转矩千分比定义目标。
- 6076、6077（237页）给出额定转矩mN·m及同标尺的反馈。
- 手册表格仍写额定电流千分比，措辞并不完全一致。本工具按6071详细定义生成
  **名义目标转矩**，并独立展示6077反馈，不宣称精确的物理力矩或独立传感器闭环。
- 不使用CSF模式13；它采用另外的模组转矩标尺，不能套用本换算。

每次按键累加整数步数，启动时实读各轴非零6076，按累计目标重新量化：

```text
请求Nm = 步数 × 0.05
6071整数指令 = round(步数 × 50 mNm × 1000 / 6076)
量化名义Nm = 6071 × 6076 / 1000000
驱动反馈Nm = 6077 × 6076 / 1000000
```

例如实读6076为3600 mN·m时，0.05 N·m量化为14，对应0.0504 N·m；
累计0.25 N·m量化为69，对应0.2484 N·m。因此不能每次固定累加14。
显示的请求值、量化指令及驱动反馈是三个不同值。
不将减速比乘入电机侧指令，不硬编码历史额定值；缺失标尺或无法表示目标时拒绝操作。

## 保护边界

沿用CST的零6071、零60B2读回确认后再使能。指令限制为±1000‰；请求值和量化值
均不得超过配置的转矩阈值，超出时保留上一有效目标并提示拒绝。
任一所选轴反馈绝对转矩超过100 N·m（可显式配置），或必要反馈、通信异常时，
周期线程切断共享电源并锁存故障，不重试和自动恢复。
反馈管道使用非阻塞写入和100 ms超时，前端停止读取时会退出并走优先断电路径，
不会因反馈输出一直阻塞而维持原转矩。清零操作先清所有已使能轴目标，再逐轴确认失能。

转矩模式将 `--speed-rpm` 用作输出轴速度软件断电阈值，默认为1 RPM。
这是主控制线程的反馈检查，不是驱动内部限速，也不保证速度绝不越过阈值。
它与周期线程内的转矩/通信保护不同；Linux调度、通信和电源硬件均会影响实际响应。
其他轴的使能、模式切换和退出等待可能推迟主线程的速度检查；周期线程中的转矩及通信保护仍独立运行。
源码与模拟测试可验证指令和故障流程，实际出力、方向和断电延迟仍需实机验证。
